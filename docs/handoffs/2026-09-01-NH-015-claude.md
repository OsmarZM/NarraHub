## O que foi feito

O app deixa de morrer em silêncio quando o banco é mais novo do que ele entende.

**Rust.** Comando `database_compatibility`, separado do `database_health` por dois motivos
que só aparecem num caminho de boot: não roda `integrity_check`, `foreign_key_check` nem as
consultas de invariante — caras num banco de vários MB — e **não falha quando o banco ainda
não existe**, que é o primeiro boot de toda instalação nova. Abre em
`SQLITE_OPEN_READ_ONLY`, então não há como corromper o que se quer proteger.

**Bootstrap.** A verificação acontece antes de `db.init()`. Banco incompatível interrompe a
inicialização sem abrir o pool.

**Interface.** `SchemaRecoveryComponent` mostra os dois números de schema, afirma que os
dados estão intactos, e oferece atualizar (ação primária) ou voltar por backup.

## Decisões de desenho que valem sobreviver

**Incompatibilidade volta como dado, nunca como `Err`.** Um portão que estoura devolveria o
app exatamente ao defeito que ele existe para corrigir. Há um teste só para isso:
`incompatibilidade_e_resposta_e_nao_erro`.

**A lista de backups exclui os incompatíveis.** Oferecer um backup que também não abre seria
repetir o problema dentro da solução. O filtro usa `backup.schemaVersion <=
supportedSchemaVersion`, campo que o manifesto já carregava.

**A tela não injeta o `DatabaseService`.** Ela existe justamente para quando o banco não
abre; depender dele seria circular. Fala só com `BackupService` e `UpdateService`, que são
comandos Rust e funcionam sem o pool.

**Restaurar avisa que perde trabalho.** O texto diz, antes de confirmar, que o trabalho
feito depois da data do backup se perde. É o preço de voltar e não há como evitá-lo — mas
perder sabendo é aceitável, perder sem saber não é.

## Gates

- Rust, 5 testes, incluindo banco em `LATEST + 1`, banco ausente e banco mais antigo.
- `tests/frontend-boundaries.test.mjs`: compara a **posição** das duas chamadas no
  `AppBootstrapService`. Verificado por mutação — inverter a ordem reprova com
  "a verificação de compatibilidade tem que vir ANTES de abrir o pool".

Um detalhe engraçado e útil: a primeira versão do teste de fronteira reprovou o meu próprio
componente, porque procurava a palavra `DatabaseService` e achou dentro de um comentário que
dizia que ele **não** era usado. A asserção virou `inject\(DatabaseService\)`. Asserção sobre
prosa pega prosa.

## Limite que não dá para consertar

**Versões já publicadas continuam sem a tela.** A 0.8.0 é imutável; quem voltar para ela vai
continuar com um app que não abre. O portão só protege downgrades feitos a partir da
primeira versão que o contiver. Não há como consertar o passado — só parar de produzir esse
futuro.

## O que NÃO foi verificado

**A tela rodando.** O app precisa do runtime Tauri e o tooling de browser desta sessão não
consegue dirigi-lo. O comportamento está testado; a aparência não foi vista.

Para ver de verdade, sem arriscar o perfil de uso: aponte um perfil descartável para um
banco com schema maior que o `LATEST_SCHEMA_VERSION` e rode `npm run desktop:qualification`,
que usa `com.narrahub.app.qualification`.
